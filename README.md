# Wazuh Detection Engineering & Security Dashboards

A practical collection of custom **Wazuh decoders, detection rules, and Vega/OpenSearch dashboards** developed for SOC monitoring and security operations.

The repository focuses on turning raw security telemetry into structured Wazuh alerts and usable SOC dashboards.

## Scope

Current components include:

- Custom UniFi log decoders
- Custom UniFi detection rules
- UniFi Access Point, Switch, Gateway and firewall event coverage
- Wazuh File Integrity Monitoring dashboard
- FortiGate security dashboard
- FortiSwitch security dashboard
- A dashboard artifact currently retained separately for review because its present source content appears to use the FortiGate decoder/query rather than a distinct threat-intelligence data source

## UniFi detection engineering

The UniFi decoder set covers multiple log families rather than treating all UniFi events as a single generic message.

Current decoder coverage includes:

- UniFi Gateway
- UniFi Switch
- UniFi Switch link state
- UniFi AP kernel events
- UniFi AP neighbor updates
- UniFi AP client association tracking
- UniFi AP system events
- UniFi firewall events

The corresponding rules classify events such as:

- AP kernel messages
- AP process events
- AP neighbor discovery/update activity
- Client association events
- Wi-Fi radio subsystem restarts
- RRM channel scans
- Failed client associations
- Client DNS timeouts
- Switch port link state changes
- STP port role changes
- Gateway memory events
- Firewall traffic
- QUIC / UDP 443 traffic
- HTTPS / TCP 443 traffic
- Unencrypted HTTP / TCP 80 traffic

## Dashboard engineering

The dashboards are implemented as Vega specifications querying Wazuh alert indices.

### File Integrity Monitoring

The FIM dashboard extracts Wazuh `syscheck` information including agent identity, monitored object path, event type, permissions, ownership, changed attributes and rule metadata.

### FortiGate

The FortiGate dashboard is designed around firewall, authentication, VPN and security events. It extracts fields such as firewall identity, severity, event type, source/destination information, user, action, service and protocol.

### FortiSwitch

The FortiSwitch dashboard is designed around switch events, device identity, severity, event type, source information, interface and protocol/action fields.

## Important review note

The supplied `SIEM threat intelligence dashboard` artifact currently contains the same dashboard structure and FortiGate decoder filter used by the FortiSwitch artifact. It has therefore been kept under a review directory instead of being presented as a verified threat-intelligence dashboard.

Before publishing that artifact as a finished component, replace it with the intended threat-intelligence dashboard or update its query/data model.

## Installation

### Custom decoders

Copy the required decoder definitions into the Wazuh manager's custom decoder configuration:

```text
/var/ossec/etc/decoders/
```

Validate the decoder against representative logs before deploying it to production.

### Custom rules

Copy the required rule group into the Wazuh manager's custom rules configuration:

```text
/var/ossec/etc/rules/
```

Validate the rules with representative events and confirm the generated alert fields before production use.

### Vega dashboards

Import the Vega specifications into the Wazuh/OpenSearch dashboard environment and adjust the index pattern and field mappings if your environment differs.

## Validation

These artifacts should be tested against the actual log format generated by the target product.

Recommended workflow:

1. Capture representative raw logs.
2. Test decoder matching.
3. Confirm extracted fields.
4. Test rule conditions.
5. Verify alert severity and grouping.
6. Validate dashboard queries against generated alerts.
7. Test edge cases and malformed/unexpected events.
8. Deploy only after validation in a controlled environment.

## Privacy and operational safety

Do not publish:

- Client names or internal identifiers
- Internal IP addresses
- Hostnames
- Usernames
- Email addresses
- API keys, tokens or credentials
- Private URLs
- Production alert samples containing sensitive information

Dashboard screenshots should be sanitized before publication.

These configurations are provided as security engineering examples. Test and adapt them to your own Wazuh version, log format, environment and operational requirements before production deployment.
